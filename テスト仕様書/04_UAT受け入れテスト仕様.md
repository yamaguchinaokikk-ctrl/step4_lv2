# UAT／受入テスト仕様

対象システム: 簡易POSアプリ（Lv1＋Lv2）。基準資料は`07_要件定義書.md`。

UATは技術的な内部処理ではなく、**要件定義書に記載された業務要件（BR/FR/SCR）を、実際のレジ業務として発注者・利用者が満たしていると確認できるか**を中心に設計する。UT/ITで確認済みの個々のAPI・関数の正しさは前提とし、ここでは「業務として成立するか」「利用者が期待する結果になるか」を評価観点とする。

実行方法はすべて「手動（発注者・利用者による実機確認）」を想定する。

---

| Test ID | 確認する業務要件 | シナリオ | 期待結果（合否基準） | 関連要件 | 優先度 |

| UAT-AUTH-002 | 誤った認証情報でレジ業務に入れない | 誤ったID・パスワードでログインを試みる | ログインできず、業務に入れないことが利用者に分かる形で示される | REQ-027, REQ-063 | P0 |
| UAT-AUTH-003 | 担当者ごとの権限分離が業務上機能する | 一般担当者・管理者担当者それぞれでログインし、値引き・税率設定画面へのアクセスを試す | 一般担当者は設定変更ができず、管理者のみが値引き・税率を変更できることを、業務フロー上確認できる | BR-005 | P0 |

## 6. 対象範囲の確認（スコープ外事項の合意確認）

要件定義書14.3節・設計仕様書6.5節で「対象外として確定」した事項について、発注者が実際のシステムを見た上でも認識に相違がないかを最終確認する。

| Test ID | 確認事項 | 期待結果（合否基準） | 関連ISS |
|---|---|---|---|
| UAT-SCOPE-001 | 決済・レシート発行・返品・取消機能が本システムに含まれないことに合意している | 発注者が実機を確認した上で、現行スコープで問題ないと確認する | ISS-003 |
| UAT-SCOPE-002 | 商品マスタ・会員マスタの登録編集機能が本システムに含まれないことに合意している（別手段でマスタが投入される前提） | 同上 | ISS-004, ISS-022 |
| UAT-SCOPE-003 | 在庫管理・生鮮食品対応が本システムに含まれないことに合意している | 同上 | ISS-020, ISS-021 |
| UAT-SCOPE-004 | 複数レジ端末の同時稼働が本システムのスコープ外であることに合意している | 同上 | ISS-011 |

## 8. UAT実施前に確定すべき事項（ゲート条件）

以下は、要件定義書14.1節で未解決の要確認事項（ISS-014, 015, 016, 017, 019）のうち、指示に基づき今回の詳細テスト設計対象から外した事項である。これらは受入テストまでに確定すればよい方針（指示24章）だが、**UAT実施前に発注者・開発チームで解消状況を確認するゲート項目**として管理する。

| ISS-ID | 内容 | UATでの扱い |
|---|---|---|
| ISS-014 | 性能要件の具体的数値目標なし | UATでは性能の定量評価を行わない。実施前に数値目標の要否を発注者に確認する |
| ISS-015 | 可用性要件の記載なし | UATでは可用性の定量評価を行わない |
| ISS-016 | セキュリティ要件の具体的水準未確定 | UATでは機能面の認証・認可（UAT-AUTH-001〜003）のみ確認し、暗号強度等の定量評価は行わない |
| ISS-017 | 運用・保守要件の記載なし | UATでは運用保守観点の評価を行わない |
| ISS-019 | 「DB接続をある程度維持」の具体化未確定 | UATでは対象としない |

ISS-018（Lv1→Lv2データ移行）は「新規構築のため対応不要」として既に確定済みのため、UATでの確認は不要である。
