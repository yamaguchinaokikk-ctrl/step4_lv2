# ISS管理（テスト設計における未確定事項の管理）

要件定義書14章・設計仕様書9章のISS一覧のうち、テスト設計・テスト実施に関わるものを整理する。本書はISSそのものを解消するものではなく、テスト設計の観点から「詳細テストケースを設計するか／しないか」を判断した記録である。

## 1. 詳細テスト設計の対象から外したISS（指示24章に基づく）

以下は、要件定義書14.1節で未解決の事項のうち、優先度目安が「低」（受入テストまでに確定すればよい）とされた事項、および中優先度だが数値目標を伴わない事項である。指示に基づき、今回の詳細なテスト設計対象からは外し、UAT／受入テストまでに確定・対応が必要な管理項目として記録する。

| ISS-ID | 内容 | 優先度目安 | テスト設計での扱い | 管理状況 |
|---|---|---|---|---|
| ISS-014 | 性能要件の具体的な数値目標なし | 低 | 性能テストのテストケースを設計しない | UAT実施前に発注者へ数値目標の要否を確認（`04_UAT受け入れテスト仕様.md` 8章） |
| ISS-015 | 可用性要件の記載なし | 低 | 可用性テストのテストケースを設計しない | 同上 |
| ISS-016 | セキュリティ要件の具体的水準未確定 | 低 | 暗号強度等の定量評価は設計しない。認証・認可の機能面はIT/E2Eで検証 | 同上 |
| ISS-017 | 運用・保守要件の記載なし | 低 | 運用保守テストのテストケースを設計しない | 同上 |
| ISS-019 | 「DB接続をある程度維持」の具体化未確定 | 中 | 非機能テストのテストケースを設計しない | 実装着手前に具体化が望ましい（要件定義書優先度目安） |

**ISS-018**（Lv1→Lv2データ移行）は「新規構築のため移行対象データなし、対応不要」として要件定義書14.3節で既に確定済みであり、テスト設計・UATいずれにおいても対応不要である。

## 2. テスト設計に影響した「部分解消」ISS

| ISS-ID | 内容 | テスト設計での扱い |
|---|---|---|
| ISS-002 | Lv2独自要素の画面イメージがない（部分解消） | E2Eテストの操作手順を`[AI提案]`のワイヤーフレーム案に基づく暫定手順とした（`03_システムE2Eテスト仕様.md`冒頭に明記） |
| ISS-009 | バーコードスキャン失敗時の挙動（部分解消：商品マスタ未登録エラーはFR-023として確定） | E2E-BARCODE-004（スキャン失敗自体）の期待結果を`要確認`とし、E2E-PURCHASE-004・IT-PROD-003（商品マスタ未登録）は確定ケースとして扱った |

## 3. テストケースの期待結果が「要確認」となった項目一覧

要件定義書・設計仕様書に根拠がなく、期待結果を確定できなかったテストケースを集約する（詳細は各ファイル参照）。

| 項目 | 該当テストケース（代表） | 未確定の内容 |
|---|---|---|
| 金額計算の丸め処理 | UT-BE-CALC-005, UT-BE-TAX-005 | 端数（切り捨て／切り上げ／四捨五入）の方法が要件定義書・設計仕様書のいずれにも記載がない |
| 税率「該当なし」時の挙動 | UT-BE-RATE-006 | 対象日以前に有効な税率が存在しない場合の戻り値・例外が設計仕様書5.2節に記載なし |
| calculateTotals明細0件時の挙動 | UT-BE-TAX-006 | 関数レベルでの0件時の戻り値・エラーは未規定 |
| 取引合計金額の上限超過時の挙動 | UT-BE-VAL-TOTAL-002, UT-BE-TAX-008 | 6.2節に上限値の記載はあるが、超過時のエラーコードが6.3/6.4節に明記なし |
| パスワードの記号使用可否 | UT-BE-VAL-PASS-007 | 「英数字両方を含む」以上の文字種規定が設計仕様書6.2節にない |
| 商品コードの文字種 | UT-BE-VAL-PRODCODE-005 | 桁数（8〜13桁）のみ規定、数字以外の文字を許容するかの記載がない |
| バーコード読み取り失敗時の挙動 | E2E-BARCODE-004, E2E-BARCODE-006 | ISS-009未解決（部分解消のみ）、FR-020自体が`[AI提案]` |
| ログインロックアウトの具体的回数・時間 | UT-BE-AUTH-LOCK-006, E2E-LOGIN-003 | 5回・15分は`[AI提案]`の暫定値、`[要確認]`のまま |
| アイドルタイムアウトの具体的時間 | E2E-LOGIN-004 | 10分は`[AI提案]`の暫定値 |
| 値引き削除後の関連取引明細の扱い | （テストケース未設計） | 値引き削除（IT-DISC-006）後、既に確定済みの取引明細（discount_id参照）への影響は設計仕様書に記載なし |

これらは実装着手後、発注者・開発チームでの確認を経て期待結果を確定し、該当するUT/IT/E2Eテストケースを更新すること。
