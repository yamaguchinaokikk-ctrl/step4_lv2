# 単体テスト仕様（UT）

対象システム: 簡易POSアプリ（Lv1＋Lv2）。基準資料は`07_要件定義書.md`・`設計仕様書.md`（`00_テスト仕様書.md`参照）。

**前提**: 実装コードが存在しないため、テスト対象は設計仕様書5.3節（クラス図）・6.2節（設定値定義）に記載されたメソッド・バリデーション仕様である。メソッドの実際のシグネチャ・例外型・戻り値の詳細は詳細設計・実装時に確定する。本書のテストケースは、実装時にメソッド名・引数名が変わった場合でも「何を検証すべきか」が引き継げるよう、検証内容（入力・期待結果）を仕様ベースで記述している。

日付に依存するテスト（`isActive`、`getCurrentRate`）は、システム日時を固定またはモック化できることを前提とする（`[AI提案]`）。

## 1. Discount.calculateAmount(unitPrice, quantity) — 値引き額計算

| 項目 | 内容 |
|---|---|
| 対象 | `Discount.calculateAmount(unitPrice, quantity)`（設計仕様書5.3節） |
| 関連要件 | FR-011, FR-012, DR-003 |
| 関連設計 | 設計仕様書3.1節F-05、5.3節（計算式）、5.2節DISCOUNTS |
| テスト技法 | 境界値分析（値引率0/100%、値引額の上下限、数量1/99）、同値分割（discount_type） |
| 前提条件 | Discountオブジェクトはすでにバリデーション済み（discount_value等の範囲チェックはUT-BE-VAL側で検証済みのものを前提とする。本節は計算式の正しさのみを検証する） |
| テストデータ | `05_テストデータ設計書.md` TD-PRODUCT-04（unitPrice=1000の値引き対象商品）、TD-DISCOUNT-01/02参照 |
| 実行方法 | pytest（バックエンド） |

**計算式（根拠：設計仕様書5.3節）**: `discount_type='rate'` → `unitPrice × quantity × (discount_value / 100)`。`discount_type='amount'` → `discount_value × quantity`（discount_valueは商品1個あたりの値引き額）。
