# 要件－テストケース トレーサビリティマトリクス

要件定義書（`07_要件定義書.md`）の各要件ID（BR/FR/SCR/DR/IF/NFR/CON/ASM）が、どのテストケースで検証されるかを示す。「このテストケースは、どの要件を確認するために存在するのか」を追跡できることを目的とする。

凡例: UT=単体テスト、IT=結合・機能テスト、E2E=システム/E2Eテスト、UAT=受入テスト。「―」はテストケースを設計していない項目（理由を備考に記載）。

## 7. カバレッジサマリ

| 観点 | 結果 |
|---|---|
| 要件カバレッジ（BR/FR/SCR/DR、動的テストが可能な要件） | 55件中52件に直接対応するテストケースあり（約95%）。残り3件（FR-020、DR-008、NFR-SEC-001）は要件定義書・設計仕様書の時点で未確定（`[要確認]`）のため部分的カバレッジに留まる |
| IF/NFR/CON/ASM | 性質上、動的テストではなく設計レビューでの確認が適切な項目が中心（IF-001, CON-001〜007, ASM-001〜003）。NFR-PERF-001はISS-014未解決のためテスト対象外 |
| 機能カバレッジ（設計仕様書3章F-01〜F-10） | F-01〜F-08はUT/IT/E2Eで網羅。F-09（単価変更履歴記録）はDR-008同様に間接確認のみ。F-10（値引き・税率管理）はIT/E2Eで網羅 |
| 分岐カバレッジ | `Discount.calculateAmount`のrate/amount分岐、`TaxService.getCurrentRate`の該当/非該当分岐、認可判定のstaff/admin分岐など、主要な分岐は境界値分析・デシジョンテーブルで網羅（01章参照） |
| 異常系カバレッジ | 各バリデーション項目に対し、上限/下限の境界異常値・型不正・存在しないID等を網羅（01・02章参照）。正常系のみに偏っていない |
| E2Eカバレッジ | ログイン、商品登録（スキャン／手入力）、購入リスト操作、会員・値引き、購入確定、バーコード読み取り、管理者機能の主要業務フローを網羅 |
